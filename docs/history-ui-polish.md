## 1. 変更前UIの課題

POより「機能の実装は問題ない。だが、UIが素っ気なさ過ぎる」との評価を受け、改善前のUIを分析した結果、以下の構造的課題を抽出しました。

1. **極度にフラットで無機質な情報階層**:
   - 白背景に1pxグレーボーダー、標準の黒文字のみで構成され、カードや領域ごとの視覚的重力・親子関係が判別しづらい。
   - ブラウザ標準のネイティブフォーム部品（生ラジオボタン、素のセレクトボックス、枠線のみのテキスト入力）がそのまま配置され、専用アプリとしての道具感が欠如していた。
2. **閲覧経路（Navigation Journey）の文脈断絶**:
   - 訪問詳細（Slice 3）において、「訪問情報」「遷移元」「遷移先」「取得したページ情報」が縦に機械的に並ぶだけで、Memocampusの最大の特徴である「どこから来て、どうナビゲートされ、次にどこへ行ったのか」という時系列の因果関係が視覚的に伝わらなかった。
3. **時系列アンカーとしての弱さ**:
   - 訪問一覧の時刻列（`visit-time`）がただのテキストとして配置され、一日の行動履歴としての連続性やタイムライン感が希薄だった。
4. **操作状態・選択状態のフィードバック不足**:
   - 行を展開した際、どの行が開いているのか周辺の行と境界が溶け込み、視線が迷子になりやすかった。
   - 完全一致／正規表現の切替が小さな丸ラジオボタンで操作しにくく、現在どちらが選ばれているかの視認性が低かった。

## 4. コンポーネント別の詳細改善

### 4.1 カレンダー（サイドバーURLタブ準拠の年月ピッカー＋◀ ▶ナビゲーション）
- **サイドバーURLタブとの機能統一**:
  - 前月移動を `◀`、翌月移動を `▶` に統一。
  - タイトルを `${shown.year} ▼ ${shown.monthIndex + 1}月` のインタラクティブなボタン（`cal-title`）とし、クリックで年月ピッカー（`months` ビュー）を開閉可能に刷新。
  - 年月ピッカー内ではタイトルが `${pickerYear} ▲` となり、`◀` / `▶` で年の移動（`pickerYear -= 1` / `pickerYear += 1`、ホスト要求は送信せずクライアント内で即時切替）。
  - 1月〜12月の12個の月ボタン（`.calendar-month`）を4列グリッドで配置。月選択で該当月のカレンダー日グリッド（`cal-table`）へ復帰し、閲覧日データを読み込み。
  - タイトル再クリックや Escape キー押下で、月を変更せずに日グリッドへ安全に復帰。
- **カードの独立化**: 12pxの角丸と繊細なボックスシャドウを持つ独立カードとして再構築。
- **セル（日付）の視覚的洗練**:
  - 正方形に近いゆったりした丸角ボタン（34px四方、8px radius）。
  - 等幅タブラ数字（`tabular-nums`）を採用し、桁数によるブレを排除。
  - **今日（is-today）**: アクセントカラーの繊細なリング（インセットボーダー）。
  - **選択日（is-selected）**: アクセントカラーのベタ塗りと純白テキスト、控えめなドロップシャドウで最前面に強調。
  - **訪問あり（has-visits）**: セル下部中央に配置された洗練された5pxドットインジケータ。選択時は白色、未選択時はアクセントブルーで明瞭に発光。
- **操作性**:
  - 選択月以外を表示している際に出現する「選択中の日の月へ戻る」（`cal-jump`）は、専用のピルボタンとして目立たせ、迷わず復帰可能に。

### 4.2 ドメイン検索・モード切替
- **セグメントコントロール（Segmented Control）**:
  - 従来の生ラジオボタンを撤廃し、macOS/iOSネイティブライクなピル型セグメント切替（`[ 完全一致 ] [ 正規表現 ]`）をCSS `:has()` により実装。
  - ネイティブの `<input type="radio">` を内部に保持したまま視覚的に昇華させているため、キーボード操作（矢印キー・Tabキー）やスクリーンリーダーのアクセシビリティ、テスト互換性は完全維持。
- **検索入力欄**:
  - 角丸8px、高コントラストなフォーカスリング（`outline: 2px solid var(--accent)`）。
- **フィードバック**:
  - `domain-error` は柔らかな警告赤背景と赤ボーダーの角丸アラートバナーとして表示。

### 4.3 訪問一覧（タイムラインストリーム）
- **日付ヒーロー見出し**:
  - `2026年11月17日（火）` を堂々たる18pxのボールド見出しとして配置し、その横に総件数を示すピルバッジ（`124件`）を配置。
- **各訪問行（`.visit-row`）のストリームカード化**:
  - 行を単なるテーブル罫線ではなく、角丸8pxのストリームアイテムとしてスタイリング。ホバー時に微細な背景変化。
  - **展開行のハイライト**: 詳細が開いている行（`aria-expanded="true"`）は、左辺に3.5pxのアクセントカラー境界線（`border-left`）が現れ、背景色が一段明るいアクティブトーンへ切り替わることで、一覧の中で「今どの行を精査しているか」が一目瞭然。
- **タイポグラフィと主従関係**:
  - タイトル（`.visit-link`）: 14.5px、`font-weight: 600`、深い文字色で第一の視覚アンカーに。
  - ホスト名（`.visit-host`）: 背景付きの角丸チップタグ（`background: var(--chip-bg)`）として独立させ、走査時にドメイン名だけを瞬時に拾い読み可能に。
  - URL（`.visit-url`）: モノスペース調の11.5pxで控えめに配置し、長文は美しく1行省略。
- **展開トグルボタン（`.visit-toggle`）**:
  - 「詳細を表示 ▾」／「詳細を閉じる ▴」のマイクロピルボタンに刷新。開閉状態が矢印アイコンで直感的に分かる。

### 4.4 遷移詳細（Navigation Flow Pipeline）
Memocampusの核心である「閲覧の因果関係」を表現するため、従来の単なるカードの積層から、**時系列ナビゲーションパイプライン**へと再設計しました。

```
┌──────────────────────────────────────────────┐
│  ↑ 遷移元 (Source)                            │
│    Came from: GitHub Issue #41               │
│    https://github.com/...                    │
└──────────────────────────────────────────────┘
                       ↓ 遷移（この訪問へ）
┌──────────────────────────────────────────────┐
│  ● この訪問 (Current Page)                    │
│    タイトル: Memocampus - Local Web Vault    │
│    完全URL:  https://memocampus.local/...    │
│    記録された遷移の種類: link / typed         │
└──────────────────────────────────────────────┘
                       ↓ 後続遷移（この訪問から）
┌──────────────────────────────────────────────┐
│  ↓ 遷移先 (Targets)   [ 3件 ]                 │
│    ├ Target 1: Docs                          │
│    └ Target 2: Options                       │
└──────────────────────────────────────────────┘
                       ↓ （存在する場合）
┌──────────────────────────────────────────────┐
│  ℹ 取得したページ情報 (Page Metadata)          │
│    OGP・説明文・ファビコン情報                │
└──────────────────────────────────────────────┘
```

- **視覚的順序の最適化**:
  - HISTORY-06修正後はDOM順そのものを `遷移元 → この訪問 → 遷移先 → ページ情報` に統一。正のtabindexやCSS orderで順序を補正しない。
  - 位置依存の遷移元テストをカードの役割で識別するよう更新し、自然なTab移動を隔離Chromeでも確認した。パイプラインの外観は維持。
  - 各カード間にCSS `::after` で「↓ 遷移（この訪問へ）」「↓ 後続遷移（この訪問から）」のフローインジケータを自動描画。
- **CENSORED と UNKNOWN の品格ある表現**:
  - `[CENSORED]`: PO採用の背景 `#FFEB3B`・文字 `#C62828`、太字・等幅（`detail-censored`）。ライト／ダーク共通、点滅・アニメーションなし。「遷移元の閲覧履歴は削除されています」を維持。forced-colorsではシステムの自動色調整を許可。
  - `unknown`: ニュートラルなスレートバッジで「遷移元：不明」を表示。「直接アクセス」と決めつけない契約を堅持。
- **遷移先リスト（`.detail-targets`）**:
  - 内部スクロール（`max-height: 24em; overflow-y: auto`）を備え、各遷移先端をネストされたマイクロカードとして描画。

## 5. 非同期・Privacy・セキュリティ契約の堅持

デザイン改善で維持する契約は以下のとおりです。最終レビューで検出された失効・非表示・順序の問題とその修正は§10に記録します。

1. **安全なDOM生成の徹底**:
   - `innerHTML`, `outerHTML`, `document.write` は不使用。テキストは `createElement`, `textContent`, `setAttribute` で構築し、無検証HTML挿入を避ける。
2. **URL安全性の保護**:
   - 外部URLリンクは `http:`, `https:` のみ `<a>` タグ化し、`target="_blank"` および `rel="noopener noreferrer"` を強制。
   - `javascript:` 等の危険なスキームや切り詰め済みURLはテキスト（`<span>`）としてのみ表示。
3. **CENSORED／UNKNOWN情報の推測・復元防止**:
   - Hostが削除済み遷移元に対して余分なプロパティを付与してきても、UI側で破棄する契約を完全維持。
4. **非同期競合防止（HISTORY-01 / 02 / 03）**:
   - 入力中のドメイン保持（`typingTimer` による保護）。
   - 画面遷移・ページ移動時の古い完全URL取得応答の確実な破棄。
   - 旧Hostの能力判定（`history_v1`）の確実な認識。
