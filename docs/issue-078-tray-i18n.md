# Issue #78 — Windows トレイ UI の日本語・英語対応

## 表示言語

- 起動時に一度だけ `GetUserDefaultUILanguage`（ユーザーの Windows 表示言語）を読む。インストーラー（#75、`LanguageDetectionMethod=uilanguage`）と同じ API。
- 主言語が日本語（LANGID の下位 10 ビットが `0x11`）なら日本語、それ以外の言語と取得失敗（0）は英語。
- 言語の設定・保存・コマンドライン引数・環境変数は**ない**。言語を変えた場合はトレイの再起動で反映される。
- 言語は文言だけを変える。項目の有効/無効、アイコン、チェック、監督・終了・設定保存・自動起動の判断は状態だけで決まり、両言語で同一（`view` のテストで全状態について比較）。
- 診断ログに `ui_language=ja|en` を 1 行出す（`--log` 指定時のみ）。

## 翻訳カタログ（`tray/src/i18n.rs`）

- 表示文字列はすべて `Key` で表し、`catalog!` の各エントリが `ja` と `en` を両方持つ。片方が無いとコンパイルエラーになり、英語から日本語へ黙ってフォールバックする経路は存在しない。
- 日本語が正本。日本語の表示は従来と同一（`view` のテストで代表文言を完全一致で確認）。
- 動的な値は `{name}` プレースホルダーと `fill` だけで挿入する（1 回の走査で埋め、値の中の `{...}` は再置換しない）。
- テストで確認すること：全キーが両言語で空でないこと、プレースホルダーが一致すること、英語に日本語の文字が無いこと、日本語が訳されていること（製品名・アドレス・ツールチップの枠だけは意図的に同一）。
- 翻訳しないもの：メニュー ID（`ACTION_IDS`）、ウィンドウクラス `MemocampusTrayHost`、非表示ウィンドウ名、ログの機械判定文字列、エラーコード（`vault_publication_pending` 等は表示内でもそのまま）、レジストリ名、プロトコル識別子。
- 操作失敗は文字列ではなく `controller::OpError`（固定コード）で保持し、`view` が言語ごとの文言にする。

## 情報表示行の色（Phase C）— PO 判断待ち

Windows 11 の標準メニューでは、操作不能な項目は `MF_GRAYED`・`MF_DISABLED`（`MF_GRAYED` なし）・アイコン付き項目のいずれも同じ灰色で描画される（隔離プローブで実測）。操作不能のまま通常の前景色で描くには、独自描画（`MFT_OWNERDRAW`）が必要になる。本 Issue の指示に従い、独自描画には着手していない。情報行は従来どおり disabled（クリック・キー操作とも何も起きない）。

## 隔離された描画確認（`tray/examples/menu_preview.rs`）

製品と同じ `ui::build_menu` と `view::view` で作ったメニューを、トレイアイコン・サーバ・レジストリ・設定ファイル・単一インスタンス制御なしで、専用のウィンドウクラスから表示する。言語と状態を引数で選び、画面キャプチャと各項目の状態（有効/無効、文字列、最も暗い画素）を書き出す。`click <位置>` / `key <回数>` で、その項目から何が届くかも記録する。

```
cargo build --examples
target\debug\examples\menu_preview.exe en error-port <出力先>
```
